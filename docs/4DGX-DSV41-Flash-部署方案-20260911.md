## 二、部署形态决策（5 条）

1. **本地权重，跳过 NFS 全链路**：四机已有 476G 权重，repo 的 NFS share 机制整体弃用——消除 exports 覆写跨栈风险（作者脚本会覆写复用容器的 /etc/exports）+ rank3 免环上两跳读。
2. **接管 8899 loopback**：proxy 8888、门户 LiteLLM 条目、hermes、RK 面板全部零改动。对照 09-05 先例「PORT 8001→8888，免改门户 config」同思路，这次连 proxy 都不用碰。
3. **契约复刻**：`API_KEY=YOUR_API_KEY`；served name 保留旧名 `deepseek-v4-flash-vision-exp`（proxy 转发的就是它）并新增 `deepseek-v4.1-flash`。
4. **环网 env 沿用已验证值**：GID=-1 铁律（绕过 repo 的自动探测）、NCCL 挂 /opt/nccl-ringonly、MERGE_NICS=0、SUBNET_AWARE_ROUTING=1、PEER_HCA per-rank。
5. **TP4 未 boot 验证 → 保守起步**：CONTEXT 262144、MAX_TOTAL_TOKENS 2M，跑通后再爬坡到 1M/4M。

**面板补丁范围**：仅 `server/collectors/LlmProbe.js` 一个文件（`_applySglangServerInfo` / `_applySglangMetrics` 各加几行）+ `systemctl restart sparkdash`。所有补的指标名已在 dev-dsv41 镜像 `metrics_collector.py` 中核实存在。前端如需 KV 卡单位适配（GiB vs %）另改。

**面板修复记录（2026-09-12）**：① 累计丢失——SGLang 路径裸计数器覆盖 totalOutputTokens，未走 token bank → 改为与 vLLM 同款 bankTokenCounters 记账；② 实时不显示——/metrics 获取被 sticky gauge 门控挡住 → 取消门控；③ 生成期间 genTps 恒 0——SGLang token 计数器**请求完成时才记账**（vLLM 是实时）→ 补 `sglang:gen_throughput` live gauge 路径（仅 requestsRunning>0 时信任，防粘滞）；④ **cached 口径**——SGLang `prompt_tokens_total` **含** cached（vLLM 不含，语义相反），未拆分导致 miss/hit 计费错 → LlmProbe 改 computed = prompt − cached 分别入账（cached 恢复增长）；⑤ **dashboard 独立轮询只解析 `vllm:*`** → 加 `sglang:*` 双解析 + `sglang:cache_hit_rate`（面板自己那套指标与 sparkdash 是两条独立链路，这是"数字不一样"的根源）；⑥ **趋势曲线崩**——今晨旧 bug 窗口期把当日基线 baseOutput 定成裸计数器值(=8) → 今日曲线 = 绝对总量 39.8M 拉爆、前 6 天压平 → 用午夜 bank 实测值重定基线并清污染点；⑦ **费用曲线 cached 双重计费**——曲线取 `input_total`(=computed+cached) 乘 miss 价、cached 又乘 hit 价 → 改取 `input`(computed) 与 `_day_cost_from_hist` 同口径（实测虚高 8.78 → 修正 7.36）。

**金额口径与验证（2026-09-12 独立重算对账）**：单价表 `PRICE_SCHEDULE`（9-10 12:00 新价：高峰 miss 2.0 / hit 0.04 / out 8.0，闲时对半；高峰=工作日 9-12、14-18 北京时）。今日金额独立重算 = ¥7.3584，面板显示 7.36 ✅；总额 = 基数 9522.13（截至 09-11 封口）+ 今日 = 9529.52 ✅。09-11 23:00 点的 output 曾因切换瞬间计数器归零被钳为 0（归档同脏）→ 用 22:00 好值 + 切换后实测产出修复为 1,357,583，8 天曲线全部单调。

**注意**：`/get_server_info` 在 dev-dsv41 中**不返回** `total_input_tokens/total_output_tokens` 顶层字段（源码已核实），面板主路径靠 `/metrics` 计数器——因此 `--enable-metrics` 从"可选"升为"面板必做"。
